# AGENTS.md — LDoE Knowledge Base

Этот репозиторий — долговременная фактическая база по Last Day on Earth: Survival.

## Перед любой работой

Прочитать:
1. `CURRENT.md`
2. `RULES.md`
3. `SCHEMA.md`
4. `INDEX.md`
5. профильный README нужного раздела.

## Основной режим

- Отвечать пользователю по-русски.
- Использовать русские игровые названия как основные.
- Английские названия хранить для поиска и сверки.
- Для изменяемых игровых данных сначала проверять свежие источники.
- После проверки полезные подтверждённые данные сохранять в репозиторий.
- Не переносить факты из памяти модели в базу без источника.
- Не заменять `null` догадкой.
- При конфликте источников обновить запись с явным описанием конфликта.

## Источники

Приоритет задаёт `RULES.md`.

Для свежих механик:
1. официальный Kefir;
2. текущий экран игры пользователя;
3. актуальная Wiki;
4. свежие подтверждения игроков.

Старые материалы допустимы только как исторический контекст.

## Обновление записи

При существенном изменении:
- обновить `checked_at`;
- указать версию игры, если известна;
- добавить/обновить sources;
- старую механику пометить `obsolete`, если она больше не работает;
- при крупном обновлении добавить запись в `updates/`.

## Практические ответы

Для запроса «я иду в локацию X» давать:
1. цель/ценность похода;
2. обязательные условия доступа;
3. что взять обязательно;
4. броню/защиту;
5. оружие;
6. инструменты;
7. врагов/боссов;
8. опасные механики;
9. самый экономичный подтверждённый маршрут;
10. что можно не брать.

Для запроса по ресурсу:
1. все актуальные способы получения;
2. стабильность каждого источника;
3. производство/рецепт;
4. переработку;
5. лучший способ для текущего прогресса пользователя.

## Git discipline

- Рабочая ветка: `main`, пока пользователь явно не изменит правило.
- Не переписывать историю.
- Не удалять подтверждённые старые данные — переносить/помечать как obsolete.
- Коммиты должны описывать конкретное обновление базы.
